# OKF v0.2 (condensed capture)

## Where the spec lives

OKF moved out of `GoogleCloudPlatform/knowledge-catalog` into its own
repository, `GoogleCloudPlatform/open-knowledge-format`. The copy that
remains under `knowledge-catalog/okf/` is described there as a frozen
snapshot, no longer maintained; its README points at v0.2 and at the
new repository.

## Frontmatter fields

Required:

- `type` — a short string identifying the concept kind (e.g. "BigQuery
  Table", "Metric"). The only absolutely required field.

Recommended: `title`, `description`, `resource` (a URI uniquely
identifying the underlying asset), `tags`.

Optional families:

- **Provenance** — `sources`, a list of the materials a concept derives
  from, external or internal to the bundle. Each entry: `resource`
  (REQUIRED; names either a concrete artifact a consumer can follow —
  an absolute URL, a bundle-relative path, or a path into a
  `references/` subdirectory — or a population/scope descriptor it
  cannot), plus optional `id` (a stable key used to attribute
  individual claims), `title`, `author` (actor convention; an authority
  signal), `usage_count` (how often the resource was exercised; an
  adoption/liveness signal), `last_modified` (when the source itself
  last changed; a recency signal). A sibling `usage_window` frames every
  `usage_count` with a `{ from, to }` datetime range.
- **Trust** — `generated: { by, at }` (how the content was produced) and
  `verified`, a list of verification events each with `by` (actor) and
  `at` (ISO 8601). Multiple entries capture independent checks; a single
  verifier may be written as one bare `{ by, at }` mapping, and
  consumers must treat that as a one-element list.
- **Lifecycle** — `status`, one of `draft | stable | deprecated`,
  defaulting to `stable`; and `stale_after`, an ISO 8601 datetime
  marking when the content becomes stale.
- **Computation** (Attested Computation type only) — `runtime`,
  `parameters`, `computation`, `executor: { resource, receipt }`,
  `attester: { resource }`.

## Paths

Each path-valued field accepts an absolute URL (e.g. `https://...`), a
bundle-relative path beginning with `/`, or a relative path (e.g.
`../computations/revenue.md`).

## Actor convention

Identity fields (`generated.by`, `verified[].by`) use one convention:
`<producer>/<version>` for agents and tools, `human:<id>` for a person,
`process:<id>` for an automated process. Consumers that classify trust
key off the `human:` prefix, so producers must use it for hand-authored
or human-confirmed content.

## Extensions

Producers MAY include any additional keys. Consumers SHOULD preserve
unknown keys when round-tripping and MUST NOT reject documents with
unrecognized fields.

## Reserved documents

- `index.md` — optional directory listing for progressive disclosure.
  No frontmatter, except the bundle-root `index.md`, which may declare
  `okf_version`. Body is grouped lists with descriptions.
- `log.md` — optional chronological update history. `## YYYY-MM-DD`
  headings, newest first; prose entries with conventional prefixes
  (`**Update**`, `**Creation**`).

Version declaration: bundles may declare a target version via
`okf_version: "0.2"` in the bundle-root `index.md` frontmatter only.

## Changes from v0.1

Breaking:

- `timestamp` replaced by `generated: { by, at }`.
- The `# Citations` body list replaced by the `sources` frontmatter
  field.

Additions:

- The trust, lifecycle, and provenance families in full.
- The `Attested Computation` concept type and the `# Computation`
  conventional heading.
- The actor convention for identity fields.
